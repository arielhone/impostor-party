# מי האימפוסטר? 👀

משחק מסיבות לטלפון: כולם מקבלים שאלה, אחד מקבל שאלה קצת שונה. עונים, חושפים, מתווכחים ומצביעים.

**טכנולוגיה:** HTML/JS נקי + Firebase (Hosting, Auth אנונימי, Firestore). אין שרת, ומספיקה התוכנית החינמית (Spark).

**האתר:** https://imposter-c9f06.web.app

## הקמה (פעם אחת, כ-10 דקות)

1. **צור פרויקט** ב-[Firebase Console](https://console.firebase.google.com).
2. **Authentication** ← Get started ← Sign-in method ← הפעל **Anonymous**.
3. **Firestore Database** ← Create database ← Production mode ← אזור `eur3` או `europe-west`.
4. **Project settings** ← Your apps ← הוסף Web app ← העתק את ה-`firebaseConfig` אל `public/firebase-config.js`.
5. ב-`.firebaserc` החלף את `YOUR_PROJECT_ID` במזהה הפרויקט שלך.
6. פריסה:
   ```bash
   npm i -g firebase-tools
   firebase login
   firebase deploy
   ```
7. פותחים את `https://YOUR_PROJECT_ID.web.app` ומשחקים.

## בדיקה מקומית

```bash
firebase emulators:start
```
פותחים את `http://localhost:5000` בכמה חלונות (חלון רגיל וחלון גלישה בסתר מקבלים שחקנים שונים). במצב הזה האתר מתחבר אוטומטית לאמולטור ולא לפרויקט האמיתי. האמולטור דורש Java.

**בלי Java:** אפשר להגיש את `public` מכל שרת מקומי, למשל `python -m http.server 8123 --directory public`, ולפתוח את `http://127.0.0.1:8123`. האתר יעבוד מול הפרויקט האמיתי, עם ה-rules שכבר הועלו.

**אחרי שינוי:** `firebase deploy --only hosting` לקוד בלבד, או `firebase deploy` כשגם `firestore.rules` השתנה.

## מהלך המשחק

| שלב | מה קורה | איך עוברים לשלב הבא |
|---|---|---|
| לובי | נכנסים עם קוד או QR. המנהל יכול לכתוב זוג שאלות משלו לסיבוב הבא | המנהל לוחץ "התחל" (לפחות 3 שחקנים מחוברים) |
| מענה | כל אחד רואה רק את השאלה שלו. המנהל יכול להחליף שאלה (🔄) אם כבר הייתה | אוטומטית כשכולם ענו, או שהמנהל לוחץ "חשוף עכשיו" |
| דיון | התשובות, השאלה הרגילה וטיימר | הטיימר נגמר **או** רוב השחקנים לחצו "מוכן להצביע" |
| הצבעה | הצבעה סודית | אוטומטית כשכולם הצביעו |
| תוצאות | מי הודח, מי היה האימפוסטר ומה הייתה השאלה שלו, ניקוד | המנהל מתחיל סיבוב חדש |

**ניקוד:** כל מי שהצביע לאימפוסטר מקבל 1+. אימפוסטר שלא הודח מקבל 2+. בתיקו אף אחד לא מודח.

**הגרלת האימפוסטר:** רק מבין השחקנים המחוברים. מי שלא היה אימפוסטר הרבה סיבובים מקבל סיכוי גבוה יותר: משקל (1 + סיבובים מאז)². ההגרלה נשארת אקראית, כך שאי אפשר לנחש מי האימפוסטר.

**שאלות:** אותה שאלה לא חוזרת באותו חדר עד שנגמר הבנק. החלפת שאלה (🔄) לא נספרת כסיבוב.

**מי מחובר:** כל שחקן שולח "אני חי" כל 15 שניות. שחקן שלא נשמע ממנו 30 שניות (סגר את הטלפון) לא עוצר מעבר שלב, לא נכנס לסיבוב הבא ולא מקבל כתר. עדיין אפשר להצביע נגדו.

## אבטחה: מי רואה מה

הסודות מוגנים ב-`firestore.rules`, כך שלא אפשר לגלות אותם דרך DevTools:
- כל שחקן יכול לקרוא רק את השאלה שלו.
- התשובות נעולות לקריאה כל עוד שלב המענה פתוח.
- רשימת השאלות שכבר היו נשמרת רק אצל המנהל, כי במסמך החדר היא הייתה חושפת את השאלה הנוכחית.
- ההצבעות נחשפות רק בשלב התוצאות.

**העברת מנהל:** המנהל שולח "פעימה" כל 10 שניות. מנהל שיוצא מעביר את התפקיד לשחקן המחובר הוותיק ביותר; מנהל שנעלם (סגר טאב, טלפון בשינה) מוחלף אוטומטית אחרי כ-30 שניות. הכללים בשרת מאשרים השתלטות רק כשהמנהל באמת לא מגיב. מנהל שהטאב שלו היה ברקע מחכה לעדכון טרי לפני שהוא מעביר שלב, כדי לא לדלג על שחקנים.

**סגירת חדר:** כשהשחקן המחובר האחרון לוחץ 🚪, החדר עובר לשלב `closing` ונמחק עם כל התוכן שלו. רק בשלב הזה ה-rules נותנים למנהל לקרוא ולמחוק הכל. חדר שכולם פשוט סגרו בו את הטלפון נשאר במסד (כמה KB, זניח).

**הסתייגות:** הדפדפן של המנהל משמש "שופט" (מגריל ומעביר שלבים), ולכן המנהל יכול טכנית לגלות מי האימפוסטר דרך DevTools. זה כולל מי שקיבל את הכתר באמצע סיבוב. בין חברים זה בסדר. הגנה מלאה דורשת Cloud Functions, שמחייבות את תוכנית Blaze.

## קבצים

- `public/app.js`: כל הלוגיקה והמסכים
- `public/questions.js`: בנק השאלות (300 זוגות). כל זוג הוא `{ q: "השאלה של כולם", imp: "השאלה של האימפוסטר" }`.
- `public/firebase-config.js`: פרטי החיבור לפרויקט Firebase
- `public/style.css`: עיצוב
- `firestore.rules`: כללי האבטחה

## על המשחק

כל שחקן מקבל שאלה סודית ועונה עליה. אחד השחקנים, האימפוסטר, מקבל שאלה **דומה אבל שונה**, למשל "כמה שעות אתה ישן?" מול "כמה שעות אתה על הטלפון?". אחרי שכולם ענו, התשובות והשאלה המקורית נחשפות, מתווכחים, ומצביעים מי האימפוסטר.

- **בלי התקנה:** נכנסים מהדפדפן בטלפון עם קוד בן 4 אותיות או QR.
- **3 שחקנים ומעלה**, עם בנק של 300 זוגות שאלות, ואפשר גם לכתוב זוג משלכם.
- **עמיד לניתוקים:** טלפון שננעל לא תוקע את המשחק, ותפקיד המנהל עובר אוטומטית.
- **הסודות מוגנים בשרת:** אי אפשר לגלות את השאלה של אחר או מי האימפוסטר דרך DevTools (ראו [מודל האבטחה](#מודל-אבטחה)).

## מהלך המשחק

```mermaid
flowchart LR
    L[לובי] -->|המנהל לוחץ התחל| A[מענה]
    A -->|כולם ענו / המנהל: חשוף עכשיו| D[דיון]
    A -.->|🔄 שאלה ואימפוסטר חדשים| A
    D -->|טיימר נגמר / כולם מוכנים / אחרי הזמן המינימלי: רוב או המנהל| V[הצבעה]
    V -->|כולם הצביעו / המנהל: סגור הצבעה| R[תוצאות]
    R -->|סיבוב הבא| A
    R -->|ללובי| L
    R -->|המשחק נגמר| P[פודיום]
    P -->|משחק חדש, הניקוד מתאפס| L
```

| שלב | מה רואים | מעבר לשלב הבא |
|---|---|---|
| **לובי** | קוד חדר, QR ורשימת שחקנים. המנהל בוחר זמן דיון (1 עד 5 דקות, ברירת מחדל 2), זמן דיון מינימלי (כבוי, 15, 30 או 60 שניות, ברירת מחדל 30) ואורך משחק, ויכול לכתוב זוג שאלות משלו | המנהל לוחץ "התחל". צריך לפחות 3 שחקנים מחוברים |
| **מענה** | כל שחקן רואה רק את השאלה שלו. המנהל יכול ללחוץ 🔄 אם השאלה כבר הייתה: זה מגריל זוג שאלות **ואימפוסטר** חדשים, ובונה מחדש את רשימת המשתתפים מהשחקנים המחוברים באותו רגע | אוטומטית כשכל המחוברים ענו, או כשהמנהל לוחץ "חשוף עכשיו" |
| **דיון** | השאלה של כולם, כל התשובות וטיימר | הטיימר נגמר. לפני כן: עד הזמן המינימלי רק אם **כל** המחוברים לחצו "מוכן להצביע", ואחריו מספיק **רוב**. גם הכפתור "עבור להצבעה עכשיו" של המנהל נפתח רק אחרי הזמן המינימלי. כשהמינימום כבוי, רוב מספיק מההתחלה |
| **הצבעה** | הצבעה סודית. אי אפשר להצביע לעצמך | אוטומטית כשכל המחוברים הצביעו, או כשהמנהל סוגר |
| **תוצאות** | מי הודח, מי היה האימפוסטר, שתי השאלות, מי הצביע למי וטבלת ניקוד | המנהל מתחיל סיבוב חדש או חוזר ללובי. אם המשחק נגמר: "מי ניצח?" לפודיום |
| **פודיום** | שלושת הראשונים על פודיום וטבלה סופית. ניקוד שווה = אותו מקום | המנהל מתחיל משחק חדש, והניקוד של כולם מתאפס |

### אורך משחק

המנהל בוחר בלובי: **בלי הגבלה** (ברירת מחדל), **5, 8 או 10 סיבובים**, או **ראשון ל-10, 15 או 20 נקודות**. המשחק נגמר בסוף הסיבוב שבו הגיעו ליעד. החלפת שאלה ב-🔄 לא נספרת כסיבוב.

### ניקוד

| אירוע | נקודות |
|---|---|
| הצבעת לאימפוסטר | **+1** |
| היית האימפוסטר ולא הודחת | **+2** |
| תיקו בהצבעה | אף אחד לא מודח, והאימפוסטר מקבל +2 |

### הגרלת האימפוסטר

האימפוסטר נבחר רק מבין השחקנים **המחוברים**, בהגרלה משוקללת:

$$w_i = (1 + \text{rounds since player } i \text{ was impostor})^2$$

הספירה מתעדכנת רק לשחקנים שהשתתפו בסיבוב. שחקן שעוד לא השתתף באף סיבוב (למשל הצטרף באמצע המשחק) לא היה אימפוסטר אף פעם, ולכן מקבל את הספירה הגבוהה ביותר בחדר.

כך מצטמצמים רצפים ארוכים בלי להיבחר, וההגרלה נשארת לא צפויה. בסימולציה של 6 שחקנים ו-6 סיבובים:

| שיטה | שחקן שלא היה אימפוסטר אף פעם | אותו אימפוסטר פעמיים ברצף |
|---|---|---|
| אקראי אחיד | 33% | 16.7% |
| **משוקלל (בשימוש)** | **18%** | **2.2%** |

זוג שאלות לא חוזר באותו חדר עד שהבנק נגמר. החלפת שאלה ב-🔄 לא נספרת כסיבוב.

## ארכיטקטורה

אין שרת. כל הלוגיקה רצה בדפדפן, ו-Firestore משמש גם מסד נתונים, גם ערוץ סנכרון בזמן אמת וגם שכבת הרשאות.

```mermaid
flowchart TB
    subgraph Clients["דפדפנים (טלפונים)"]
        H["👑 מנהל<br/>השופט: מגריל ומעביר שלבים"]
        P1[שחקן]
        P2[שחקן]
    end
    subgraph Firebase
        AUTH[Auth אנונימי]
        FS[(Firestore)]
        RULES{{firestore.rules}}
        HOST[Hosting]
    end
    HOST -->|HTML / JS| Clients
    Clients --> AUTH
    Clients <-->|onSnapshot / writes| RULES <--> FS
```

**הדפדפן של המנהל הוא השופט.** הוא מגריל את השאלה ואת האימפוסטר, כותב לכל שחקן את השאלה הסודית שלו, ומעביר שלבים. שאר השחקנים רק קוראים את מצב החדר וכותבים את הפעולות של עצמם: תשובה, "מוכן" והצבעה.

### מודל נתונים

```
rooms/{CODE}                   מצב החדר, קריא לכל שחקן
│   hostUid, phase, round, participants, discussionSec, minDiscSec, createdAt,
│   discussionStartedAt, discussionEndsAt, normalQuestion, result, impSince, skipped, hostSeenAt,
│   goal ("none" | "rounds:N" | "points:N"), played, gameOver
│   (usedQ: שדה ישן, נמחק בתחילת כל סיבוב. היום הרשימה נשמרת ב-hostOnly)
│
├── players/{uid}              name, score, joinedAt, seenAt,
│                              answeredRound, readyRound, votedRound
├── secrets/{uid}              { round, q }: השאלה של השחקן, קריאה רק לו
├── hostOnly/state             { round, impostorUid, normalQ, impQ, usedQ }: רק למנהל
├── answers/{uid}              { round, text, name, at }: נעול בזמן המענה
└── votes/{uid}                { round, target }: גלוי רק בשלב התוצאות
```

לכל המסמכים יש גם שדה `expireAt`, ראו [ניקוי חדרים](#ניקוי-חדרים).

### נוכחות והעברת מנהל

| מנגנון | ערך | מטרה |
|---|---|---|
| פעימת מנהל (`hostSeenAt`) | כל 30 שניות | סימן שהמנהל פעיל |
| פעימת שחקן (`seenAt`) | כל 45 שניות | זיהוי מי מחובר |
| שחקן מנותק | אחרי 90 שניות בלי פעימה | לא עוצר מעבר שלב, לא נכנס לסיבוב הבא ולא מקבל כתר. עדיין אפשר להצביע נגדו |
| השתלטות על תפקיד המנהל | אחרי 90 שניות, ועוד 15 שניות לכל מועמד בתור | המשחק ממשיך גם כשהמנהל נעלם. התור לפי ותק נקבע בלקוח בלבד, והשרת לא אוכף אותו |

**למה המרווחים גדולים:** כל פעימה היא כתיבה, וכל כתיבה נקראת אצל כל השחקנים בחדר. הפעימות הן רוב הצריכה של מכסת Firestore החינמית (50,000 קריאות ביום). במשחק של 6 שחקנים: בערך 3,600 קריאות לשעה, כלומר כ-14 שעות משחק ביום. המחיר: שחקן שסגר את הטלפון בלי לצאת מעכב את מעבר השלב עד דקה וחצי, אלא אם המנהל מעביר ידנית.

- **מנהל שיוצא (🚪)** מעביר את הכתר לשחקן המחובר הוותיק ביותר. אם לא נשאר אף אחד מחובר, החדר **נמחק** עם כל התוכן שלו.
- **חדר שכולם פשוט סגרו בו את הטלפון**, בלי ללחוץ 🚪, **לא נמחק** ונשאר במסד עם התשובות, ההצבעות והסודות שלו (כמה KB לחדר). ראו [ניקוי חדרים](#ניקוי-חדרים).
- **מנהל שהטאב שלו היה ברקע** מחכה עד 16 שניות לעדכון טרי מהשרת לפני שהוא מעביר שלב, כדי לא לדלג על שחקנים שנראים "מנותקים" רק כי המידע ישן. אם העדכון לא מגיע בזמן הזה (רשת איטית), הוא ממשיך עם המידע שיש לו.
- **זיהוי נוכחות לא תלוי בשעון של מכשיר אחר.** כל טלפון מודד מתי *הוא* ראה את הפעימה של כל שחקן משתנה.

### ניקוי חדרים

> [!IMPORTANT]
> **כבוי כרגע.** מחיקה אוטומטית ([TTL](https://firebase.google.com/docs/firestore/ttl)) זמינה רק בתוכנית Blaze, ולא ב-Spark החינמית.

הקוד כבר מוכן: כל מסמך נכתב עם `expireAt` = עכשיו + 24 שעות. חדר פעיל לא יימחק, כי פעימת המנהל מאריכה את `expireAt` של החדר, ופעימת כל שחקן מאריכה את שלו. שאלות, תשובות והצבעות נכתבות מחדש בכל סיבוב.

ההגדרה נמצאת ב-[`firestore.indexes.json`](firestore.indexes.json), על כל אחד מששת האוספים, כי TTL לא מוחק תתי-אוספים בעצמו. כדי להפעיל אחרי מעבר ל-Blaze:

1. מוסיפים ל-`firebase.json`, בתוך `"firestore"`: `"indexes": "firestore.indexes.json"`.
2. מריצים `firebase deploy --only firestore:indexes`.

Firestore מוחק מסמכים שפג תוקפם בדרך כלל תוך יום, לא מיד. ב-Blaze, המכסות החינמיות נשארות כמו ב-Spark. משלמים רק על מה שמעבר להן.

### מודל אבטחה

הסודות נאכפים בשרת, ב-[`firestore.rules`](firestore.rules), ולא בקוד הלקוח:

| מה מוגן | איך |
|---|---|
| השאלה של כל שחקן | `secrets/{uid}` קריא רק לבעליו |
| זהות האימפוסטר והשאלות שכבר היו | `hostOnly` קריא רק למנהל |
| תשובות | חסומות לקריאה כל עוד שלב המענה פתוח |
| הצבעות | גלויות רק למנהל ובשלב התוצאות |
| ניקוד | שחקן יכול לעדכן אצלו רק שדות סטטוס, לא ניקוד |
| מעבר שלבים | רק המנהל |
| השתלטות על תפקיד המנהל | רק שחקן ששלח פעימה ב-90 השניות האחרונות, ורק כשהמנהל יצא או לא שלח פעימה 90 שניות, לפי שעון השרת. כל שחקן מחובר יכול להשתלט, לא רק הבא בתור |
| מחיקת חדר | רק המנהל, ורק אחרי מעבר לשלב `closing` |

> [!NOTE]
> **מגבלה ידועה:** המנהל הוא השופט, ולכן הוא יכול טכנית לגלות מי האימפוסטר דרך DevTools. זה כולל גם מי שקיבל את הכתר באמצע סיבוב, ולכן גם שחקן שמשתלט מ-DevTools ברגע שהמנהל לא מגיב 90 שניות. בין חברים זה בסדר. הגנה מלאה דורשת להעביר את ההגרלה ל-Cloud Functions, שמחייבות את תוכנית Blaze בתשלום.

## התקנה ופריסה

### דרישות

- חשבון Google ופרויקט [Firebase](https://console.firebase.google.com). התוכנית החינמית Spark מספיקה.
- Node.js, בשביל `firebase-tools`.

### הקמה (פעם אחת)

1. **Authentication** ← Sign-in method ← הפעל **Anonymous**.
2. **Firestore Database** ← Create database ← **Production mode**. האזור `eur3` מומלץ.
3. **Project settings** ← Your apps ← הוסף **Web app** (`</>`) ← העתק את הערכים של `firebaseConfig` אל [`public/firebase-config.js`](public/firebase-config.js).
4. עדכן את מזהה הפרויקט ב-[`.firebaserc`](.firebaserc).
5. פרוס:

```bash
npm i -g firebase-tools
firebase login
firebase deploy
```

האתר יעלה בכתובת `https://<PROJECT_ID>.web.app`.

> [!TIP]
> `apiKey` שב-`firebase-config.js` אינו סוד, הוא רק מזהה את הפרויקט. מה שמגן על הנתונים הם ה-rules.

### עדכונים

| מה השתנה | פקודה |
|---|---|
| קוד או שאלות (`public/`) | `firebase deploy --only hosting` |
| כללי אבטחה (`firestore.rules`) | `firebase deploy --only firestore:rules` |
| הכל | `firebase deploy` |

> [!NOTE]
> ב-PowerShell של Windows אי אפשר לשרשר פקודות עם `&&`. מריצים כל פקודה בשורה נפרדת.

### פיתוח מקומי

**עם אמולטור** (דורש Java). הפקודה מבודדת לגמרי מהפרויקט האמיתי:

```bash
firebase emulators:start      # http://localhost:5000
```

**בלי Java.** הקוד המקומי רץ מול הפרויקט האמיתי, עם ה-rules שכבר הועלו:

```bash
python -m http.server 8123 --directory public    # http://127.0.0.1:8123
```

כדי לבדוק עם כמה שחקנים, פותחים חלון רגיל וחלון גלישה בסתר, או דפדפנים שונים. כל אחד מהם מתחבר כשחקן נפרד.

### בדיקות

[`tests/rules.test.js`](tests/rules.test.js) בודק את `firestore.rules` מול אמולטור Firestore: שחקן לא קורא שאלה של אחר, תשובות נעולות בזמן המענה, אי אפשר לשנות ניקוד, השתלטות על המנהל רק כשמותר, ועוד. דורש Java, ולא נוגע בפרויקט האמיתי.

```bash
cd tests
npm install
npm test
```

כדאי להריץ אחרי כל שינוי ב-`firestore.rules`.

### התקנה כאפליקציה

באנדרואיד (Chrome): תפריט ⋮ ← **הוספה למסך הבית**. באייפון (Safari): שיתוף ← **הוסף למסך הבית**. האפליקציה נפתחת במסך מלא, וחוזרת אוטומטית לחדר האחרון שלא יצאתם ממנו.

אין service worker בכוונה: בלי מטמון אופליין, כל פתיחה מקבלת את הגרסה האחרונה של המשחק.

### הוספת שאלות

כל זוג ב-[`questions.js`](public/questions.js) בנוי כך:

